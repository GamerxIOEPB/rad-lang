# Rad Language Test Corpus — Bug & Feature Report

Generated by the test harness in `radtest/`. Toolchain: `radc 0.1.0` (self-hosted), bundled `rad-llc`/`rad-lld` static PIE backend, musl sysroot.
Host: Linux x86_64. Full suite: **141 test programs** in 13 categories.

## Headline results

| Status | Count | Meaning |
|---|---|---|
| PASS | 67 | Compiles and produces expected output |
| COMPILE_FAIL | 35 | Should compile but is rejected by `radc` |
| MISMATCH | 18 | Compiles and runs, but output is wrong |
| RUN_FAIL | 9 | Crashes / wrong exit code at runtime |
| NEG_OK | 5 | Invalid code correctly rejected (category `12_must_fail`) |
| NEG_BUG | 3 | Invalid code **accepted** by the compiler (unsound!) |

Reproduce: `cd radtest && runner/run_tests.sh` (requires `~/.rad/bin/radc`).
Per-test artifacts live in `results/<name>/` (stdout, stderr, compile output, exit code).

**Not counted as bugs (by design):**
- Missing semicolons are **allowed** — the language does not require `;` (removed `nf_e0001_semi` from must-fail).
- `extern "C" { … }` blocks are **not needed** — the C library (`malloc`, `free`, `puts`, `printf`, `fopen`, `exit`, …) is integrated into the prelude/linker, so `puts("hi")` and `malloc(8)` compile and run directly without any declaration (see `08_memory/mm_extern_block_probe`).

## A. What works (67 PASS)

**Basics (`01_basics`)**: hello world, printf + escapes, let/var, arithmetic & precedence, string interpolation, `main() -> i32` exit codes, comments, const, boolean logic, `println(str_var)`, argv main signature, `printf("%c")` char codes — all 11 pass.

**Types (`02_types`)**: all integer suffixes (values within 32-bit range), casts (`as u8`/`as i64`), struct field access, String build/from_str — pass.

**Control flow (`03_control_flow`)**: if/else-if/else, while, break/continue, nested loops, fizzbuzz, collatz, trial-division primes — pass.

**Functions (`04_functions`)**: basic functions, recursion (fib(20)=6765, fact(10)=3628800), mutable params, early returns, Ackermann A(3,3)=61, mutual forward recursion, value semantics, shadowing* (see bug #8), str returns, var-params — pass.

**Structs (`05_structs`)**: construction, field mutation, `impl` methods (`self`/`var self`), nested structs, `#[export_name]`/`pub extern "C"` exports, str fields — pass.

**Collections (`06_collections`)**: Vec new/push/len/ptr load/store, pop, String new/push_str/len/as_ptr/from_str, `s.len` field — pass.

**Memory (`08_memory`)**: pointer casts (`as usize`), field-index loads — pass.

**C interop (`09_c_interop`)**: `puts`/`malloc`/`fopen` work even without `extern "C"` declarations (prelude/linker resolves them) — pass.

**Stdlib (`10_stdlib`)**: argv with args, `import std` — pass.

**Complex (`11_complex`)**: matrix multiply (3×3), quicksort, Brainfuck interpreter ("Hi"), bank accounts with struct methods, mod-sum, str indexing — pass.

**Negative (`12_must_fail`)**: 5 cases correctly rejected (missing brace, unresolved identifier, type mismatch, undefined call, missing main at link time).

## B. Bug catalog

### Code generation / runtime (crashes and wrong results)

#### B1. 64-bit integers are truncated to 32 bits
- **Spec**: `type_system.md` — `i64`/`u64` are full 64-bit; literals like `5000000000i64`, `4000000000u32`.
- **Tests**: `02_types/t_i64_big` (expects `big=5000000000`, got `705032704`), `t_u32_width` (expects `4000000000`, got `-294967296`), `t_runtime64` (sum 1..999999 = 499999500000, got `1783293664` — exactly `mod 2^32`), `t_vec64_storage` (round-trip `3221225472` → `-1073741824`), `00_smoke/sm2_bigint` (`-1`), `sm3_midint`, `sm4_runtime64`.
- **Severity**: Critical — every i64/u64 program silently computes wrong results.

#### B2. f32/f64 floats crash the runtime (segfault)
- **Spec**: `type_system.md` f32/f64 exist; `best_practices.md` shows float interpolation.
- **Tests**: `00_smoke/sm2_float`, `sm3_finterp`, `sm3_fprint_var`, `02_types/t_float_interp`, `t_float_math`, `11_complex/x_roman` (SIGBUS/exit 135), `px_iso/p_float_unused` — merely `let f = 3.75f64;` segfaults at runtime even when unused. `t_float_printf` (`%.2f`) is rejected at codegen (invalid IR: ptr vs i64).
- **Severity**: Critical — all floating-point code crashes.

#### B3. `vec.ptr[index] = value` (field-index store) ICEs the backend
- **Spec**: `standard_library.md` — `vec.ptr: *raw T`; `c_interop.md` pointer writes should work.
- **Tests**: `11_complex/x_game_of_life` (`now.ptr[2*w+2] = 1` → llc error "use of undefined value `%.addr`"), `06_collections/co_vec_write`, `08_memory/mm_vecptr_ops` uses loads only (passes).
- **Workaround**: copy to a local (`let p = vec.ptr; p[i] = x;`) — verified working.
- **Severity**: High.

#### B4. `str == str` comparison emits invalid LLVM IR
- **Spec**: `migration_guide.md` implies string comparison works.
- **Tests**: `02_types/t_str_eq`, `00_smoke/sm4_str_ops` → llc error `'%3' defined with type 'ptr' but expected 'i64'`.
- **Severity**: High.

#### B5. `loop { ... }` keyword does not exist
- **Spec**: `control_flow.md` §3 documents `loop` with `break`.
- **Test**: `03_control_flow/cf_loop_probe` → `error[E0002]: unresolved identifier 'loop'`.
- **Severity**: Medium — `while true` works as a substitute.

#### B6. `match` expressions, enums, `Option`/`Result`, user generics all unresolved
- **Spec**: `pattern_matching.md`, `error_handling.md`, `structs_and_enums.md` all document these.
- **Tests**: `07_enums_match/*` (6 files: enum decl, match over enum, match over ints, Option, Result, generic enum) all → `unresolved identifier 'match'` / `'Option'` / `'State'` / `'Maybe'`.
- **Severity**: High — no sum types, pattern matching, or Option/Result in practice.

#### B7. Struct assignment aliases instead of copying/moving
- **Spec**: `ownership_and_borrowing.md` §1 — assignment moves (unique ownership).
- **Test**: `05_structs/structs_copy_probe` — `var q = p; q.x = 99;` mutates `p.x` too (got `px=99 qx=99`, expected `px=1 qx=99`).
- **Severity**: High — breaks the ownership model for structs.

#### B8. `let`-bound variable mutation is not rejected
- **Spec**: `ownership_and_borrowing.md` §2 — `let` is immutable; `x = 2` must be a compile error.
- **Tests**: `12_must_fail/nf_immut_let` → accepted (NEG_BUG); `00_smoke/sm5_neg_mutlet` runs and prints "dead".
- **Severity**: Medium — unsound w.r.t. the documented immutability rules.

#### B9. Nonexistent struct field access is accepted
- **Spec**: fields are nominal/checked.
- **Test**: `12_must_fail/nf_bad_field` — `let w = p.nope;` compiles (NEG_BUG).
- **Severity**: Medium.

#### B10. Negative-number comparison miscompiled
- **Test**: `04_functions/ft_early_return` — `classify(-3)` returns `"pos"` instead of `"neg"`; second branch misfires.
- **Severity**: High — signed comparisons broken for negatives.

#### B11. Block-local `var` shadowing does not create a new binding
- **Test**: `04_functions/ft_shadow_probe` — inner `var x = 2` leaks: outer `x` reads as `2` (got `x=2 y=2`, expected `x=1 y=2`).
- **Severity**: Medium.

#### B12. `Vec[i]` direct indexing returns garbage
- **Test**: `06_collections/co_vec_index_probe` — `v[0]` on `[42]` printed `870971424`; `00_smoke/sm3_vecidx` likewise. Only `v.ptr[i]` works.
- **Severity**: Medium (undocumented sugar, but present in grammar LValue rule).

#### B13. `Counter::new()` static constructor and `#[repr(C)]` unresolved
- **Spec**: `functions_and_methods.md` §4 shows `Counter::new(...)`; `structs_and_enums.md` §2 shows `#[repr(C)]`.
- **Tests**: `05_structs/structs_static_ctor`, `structs_reprc_probe` → `unresolved identifier 'Counter'` / `'CPair'`.
- **Severity**: Medium.

#### B14. Standard library symbols missing at codegen
- `Vec.get`/`Vec.pop` → `use of undefined value '@get'` (`06_collections/co_vec_get_probe`).
- `HashMap.insert` → undefined `@insert` (`co_hashmap_probe`).
- `eprintln`, `exit` → undefined symbols (`sd_eprintln_probe`, `xi_exit_probe`).
- **Severity**: Medium — stdlib API surface incomplete.

#### B15. N-Queens solver returns wrong count
- **Test**: `11_complex/x_nqueens` — expects n8=92/n4=2, got n8=2077481/n4=256 (every placement accepted — `place_ok` effectively always true, or recursion state corruption).
- **Severity**: High — deep recursion/backtracking broken.

#### B16. Binary search segfaults
- **Test**: `11_complex/x_binary_search` → exit 139 (segfault) on iterative search over a `Vec`.
- **Severity**: High.

#### B17. Base64 encoder emits wrong output for inputs ≥ 3 bytes
- **Test**: `11_complex/x_base64` — "fo" encodes OK, but "foo" → `Zm9i` instead of `Zm9v`, etc.
- **Severity**: Medium.

#### B18. `--emit-llvm` produces no output file
- Verified manually: exit 0, zero bytes emitted. Also diagnostics are printed to **stdout**, not stderr (all `.err` files empty).
